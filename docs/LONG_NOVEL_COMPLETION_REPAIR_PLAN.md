# 长篇完稿后的修复计划

核对日期：2026-11-11。范围是当前工作树，不是已发布安装包。本文是施工计划，不是功能发布说明。依据为作者的完稿反馈、代码检查和隔离的虚构样例；没有读取、回写原书或调用付费模型。以下示例不引用原书正文。

**最值得做的三件事：成稿对照硬规则、保住已生成的可读草稿、让作者在工作台里对全书的账。** 不再给每章 Prompt 加一页禁令，不让模型每次生成后重读整本书，也不让程序替作者改正文或确认设定。

**第二批已进入源码（P0-B，#1、#11）。** 它处理的是一条明确规则与当前正文是否冲突，不是对自由文本设定的自动理解，也不自动修改正文。

1. 打开**硬设定包**，新增或编辑一条规则。旧设定仍为“只作写作提示”。在“检查方式”里选择用语或角色动作，填入要查的词、动作、章段和例外。“仅提示作者复核”不会阻止采纳；确实不能违反的规则，选“确证违规时阻断采纳”。
2. 在**生产流水线**查看核查结果。例如，给“半步”设置全书上限后，能同时看到本章次数、已采纳正文合计、替换此章后的合计和差值。不会把已有的本章再加一次。对白、受保护的专名和设置的例外不计入用语次数，因此这不是全文搜索的命中数。角色动作分别核对主体、侧别、物件和适用状态；引语、回忆或身份不明仅供复核。只对显式条件负责，不承诺识别所有同义写法或做整篇繁简转换。
3. 核查不受 Prompt 预算限制，也不调用模型。有确证违反时，正常采纳、未审稿采纳、正式修订和恢复都不能绕过；改掉原句或调整规则即可重新核查。**章节 → 版本历史 → 核对硬设定**用现行规则核对所选正文，不改写原审稿结论。Agent 的草稿采纳建议和版本详情（`detail: "full"`）也能读到核查证据。
4. 桌面或 MCP 重复新增同项目、同条件且标题和内容完全相同的规则，复用原条目，不额外启用、覆盖或合并。编号变化或近似表述只给比较提示，由作者决定。不自动清理旧书里的重复项。

## P0：先保住正文，再拦有证据的硬伤

前置小修（#13）：整套测试入口已覆盖清单路径，直接跑子脚本却不等价。让修订测试自身显式使用独立测试清单和测试凭据来源，不继承开发机清单、主密钥或备用密钥。缺密钥断言检查“错误种类、模型调用 0 次、版本写入 0 次”；另测虚构有效密钥会走模拟传输。不要放宽断言到“随便报错就过”。不改免模型修订路线。

### A. 保留超限稿，区分有意留白和真实截断（#6、#7）

1. 正文解析后先区分：**无可读正文**（空、只有大纲、坏结构）、**可读完整候选**、**有可读片段但服务商明确中断**。对可读候选先用现有生成记录保存，再做篇幅判断和后续诊断；不把半个 JSON 当成完整正文。调用失败与“稿子已生成、待处理”应有不同结果。
2. 超出明确上限时显示“目标 1,200–1,300，实际 1,985”，保留原稿，不因字数单项自动发起第二次付费生成。作者可手修、明确要求压缩或按现有权限确认例外；作者设为硬性上限时，默认不放行正式采纳。保留现有任务契约中与篇幅无关的阻断项。
3. 供应商明确返回长度截断时，无论最后有没有句号都标记“不完整”，能安全提取的片段单独保留，不直接采纳；无结束信号时，单凭省略号、破折号、引号或无句号不足以判失败。有结构残缺等独立证据再提示检查。不要新增结尾词黑名单。
4. 复用现有 job、step、草稿 ID 与正文指纹。审计失败或重试时能从已保存候选继续，不再次调用写作模型，不重复插入草稿。桌面结果页、Agent 建议、正式提交沿用同一判定，不能一边显示“可处理”一边丢掉原稿。

**验收：**模拟模型只返回一次超长好稿，重开仍看得到原文、字数和警告；后续审稿失败再重试，写作调用数仍为 1。以 `stop`、`length`、无结束信号分别测试句号、留白、损坏 JSON、空结果；保存候选不等于采纳章节。

### B. 成稿逐条核对硬规则（#1、#11）

1. 在现有 HardCanon 编辑器为条目加**可选检查条件**；第一批只做两种：字面用语/次数，以及“谁在什么条件下能做什么动作”（角色、别名、左右侧、物件、状态、适用章段）。自由文本仍可照常使用；明确标出“只作写作提示 / 可机械核查”。不自动把自然语言或 AI 候选变成阻断规则。
2. 核查输入是**当前正文版本**与**本章适用的已启用规则**，不局限于因为预算而进了 Prompt 的子集。区别“角色甲右手持刀”“甲没有用右手持刀”“甲看到乙右手持刀”。伤势归属、持械限制、昏迷状态同理。引语、转述、指代不明、闪回或规则自身冲突，转作者复核；不能仅靠两词同段阻断。
3. 繁简与外文、重复词是可单独启用的规则。只对明确字形/词、作者给定的阈值和例外作确定判断，不借此禁止人名、型号或对白。重复用语同时显示本章次数、已采纳全书次数和采纳此稿后的差值；不把历史版本、多个草稿或示例数字当作正式计数或默认限额。
4. 接入原有质量门禁、修订后重审和正式采纳预检。结果带规则 ID、规则版本、正文指纹、原句位置及理由；确证违反作者的硬性规则才拦，弱证据只提示。旧报告正文或规则已改就重算本地检查，不额外调用模型，不冒充旧报告已经验证了新规则。
5. 桌面与 MCP 的 HardCanon 新增共用重复判断：在同项目、同作用范围内，完全相同的规则提示复用现有条目；不同编号、近义写法只提示可能重复，让作者比较。不跨项目合并，不自动停用旧规则，不把条件相反的两条合并。

**验收：**每个可执行条件至少一对正反例；同名角色、换持刀人、否定、明确左/右侧、允许外文专名均有覆盖。删改违规句后旧证据失效；恢复历史版本可重算。两处入口录入无来源的同一规则不再制造第二个有效条目。

## P1：全书对账，不再靠外部脚本通读

### A. 先把章和字数对上（#3、#10）

- 以本项目**未归档的当前正式正文**为计数基础，每章只计一次。已有非空手写或导入正文可以入账，旧章没有提交回执就标“历史正文”，不伪造回执。空壳、仅有草稿、写回失败、已正式写回、归档分开展示；完整区间与“可分配的新章号”分别返回。
- 连写模式在下一章调用模型前验证前章预期提交及其版本已落盘。若第 66 章写回失败，停在 66，给出“回到该稿 / 重试提交”；第 92 章漏写而已到 96，也能直接定位。后续手工修订写回失败与“该章有旧正文”不可混作成功。保留有意跳写、补章、归档和导入；单独开章不强行按顺序，连续任务不限 2–3 章。
- 在已有“正文累计”旁加作者可选的全书目标区间、距下限还差多少；统一首页、Agent 和章节任务显示的字数：沿用现有章节任务的去空白、含标点、按 Unicode 码点计数。虚构样本（甲、空格、换行、扩展汉字、句号）在三个入口目前分别可得 4、6、3；选区偏移量仍用原始索引，不与字数混用。可选按卷/章号范围查看，目标未知不报不足。修订、归档、恢复要替换原贡献，不把版本累加。
- 首个交付是一张“全书进度与缺章”清单，并给 Agent 返回同一结果。不要用 `max(order)+1`、job 已完成或有候选替代正式写回证明。

### B. 角色核对日期、跨章事实和全书审稿（#2、#3、#12）

| 先做什么 | 依据和处理方式 | 作者能看到什么 |
| --- | --- | --- |
| 卡片新旧 | 先让写作切片和预算估算共用同一取值：优先用九项专用字段，仅字段为空才回退到旧字段。区分“最后变化章 / 最后核对章 / 最近已确认事实章”。按本章时间点，已确认的同一状态键优先于旧卡描述；无法确认同一键时标冲突，不整段删卡。没有记录显示“未核对”，不靠更新时间猜章号；已知最后核对章就显示距当前几章，并区分期间有无已确认的相关变化。 | 卡上“核对到第 10 章，此后有一条余额变化”，可跳到证据、确认更新或保留；没变化的角色不必每章重新填卡。 |
| 钱、人数、物件 | 复用已接受的状态事实和交易，按角色、队伍、物件与单位核对；区分个人/队伍、转出/转入、明确人数/仅提到的人名。无初始金额、单位不明或少一端转移就报缺依据，不猜余额、汇率或人数。 | 数量或归属冲突给出前后两章、角色、原值和变化；草稿、被拒候选和修订前的旧版本不混进正式余额。 |
| 季节和倒计时 | 在现有时间线上按需补稳定章 ID、地点、故事时间锚点、经过时长或截止点。当前事件靠章号关联，换序要随稳定 ID 定位；迁移时有歧义就标待核。只有同一时间线、参考点可比且无跳时解释才报矛盾；回忆、异地或明确跨季的写法不误拦。 | 分开显示“第 A、B 章互相矛盾”和“两个日期之间缺时间依据”；作者可定位两处原文。 |
| 人物下落与承诺 | 分开记录最后一次**实际出场**、仅被提及、已退场/死亡、还有哪些承诺未了。未出场很久本身不是错误；只有标注待交代、承诺未结或作者选择收尾核对才提醒。 | “最后出场第 N 章”“承诺仍待处理”，可跳到来源，标明暂缓、已有交代或作者有意留白；不把所有配角建成伏笔。 |

在现有工作台提供只读的**全书核对**入口。单章采纳建议回答“这份草稿能不能采纳”；全书核对回答“哪两处正式事实冲突，还缺哪一项证据”。桌面和 Agent 查询同一结果，可按全书、卷或章号范围查看。没有卷定义时先用章号范围。

老书不要求作者先重录几十章。先列已有确认事实，再从当前正式正文中找能定位的金额、期限、承诺等线索；没有账本依据就列为“待核”，不直接计入余额或承诺。查询第 N 章时先限定事实生效范围，再选事实；当前选择器在无计划等分支能选中未来状态。缺少历史流水时不能用今天的余额倒推昨天。

跨章结论引用两端的章节 ID、版本与原句。初次按需扫描，以后章节被修订、恢复、归档或换序时，使相关结果失效；修改前章也不能继续显示旧结论为有效。不在每章写完后调用模型通读全书。

**P1 验收：**隔离的 96 章样本中放入跳号、空壳、失败写回、同一章的多个版本以及接近字数下限的情形；再放入跨季、倒数天数、物件两主、人数有出入、承诺未结及它们的合理反例。报告分别给出正确章号、差值或“资料不足”。端到端验证旧卡为十文、后来余额已确认变化时，后章 Prompt 不再并列两个“当前余额”，但回看早章不带入未来值。运行全书核对不写入正史、不产生模型费用。

## P2：费用可解释，收尾操作不用绕行

**A. 用量与连接（#5、#14）**

- **归集实耗：**通用请求还没有项目 ID，独立修订和 CLI 用量也未完整归档。新增调用记录项目、阶段、实际请求 ID；复用现有单章统计，按项目汇总写作、审稿、修订，含未采纳和重试。格式降级发出的第二个请求也应计入，同一用量上报不能重复累计。旧项目标出覆盖范围；未知不是零。
- **调用前和调用后分开：**调用前按输入、输出范围及模型价目提示预计 token 与费用；调用后显示供应商上报用量和按价目折算的金额。币种、缓存费率和缺项写清楚。无价目不报精确金额，无供应商余额接口就显示“额度未知”。订阅 CLI 不等于按 token 扣款，工作台外的通读也不能冒充已统计。
- **连接诊断：**区分余额耗尽、限流、DNS 和连接超时，说明是桌面、独立 Node 还是 CLI 子进程。仅在适用的 Node 版本和代理环境下提示检查 `NODE_USE_ENV_PROXY=1`。不输出密钥、代理凭据或整份环境变量，不为查余额试发付费正文。
- **验收：**用两个虚构项目、一次未采纳修订、重试、格式降级和缺用量的 CLI 检查不串账、不错算。用回环假服务/代理测试桌面、Node 代理启用/禁用/绕过和 CLI 替身；401、429 不误报为代理故障。

**B. 任意合理区间与正式章名（#8、#9）**

- 导向以起止章号为准，长度为正整数，5/10 留作快捷选项。类型、规范化、AI 节拍校验、Agent 世界资料接口与 Trace 一起改。旧 5/10 数据不变；起止与旧长度冲突时在预览中说明。验收第 91–96 章正好生成六个节拍，以及最后只剩一章的情况。
- 正式章名支持单章和批量操作，预览列出章号、旧名、新名，经授权和版本校验后写回。作者决定是否保留“第七章”等前缀；不改章号、不调用模型，不用空的正文修订来伪装改名。旧名可追溯。测试第 1–32 章预览不写库、重复提交不产生重复历史、并发修改不覆盖新标题。

## 交付顺序与验证

| 批次 | 最小可交付结果 | 如何决定可以进入下一步 |
| --- | --- | --- |
| 1（P0 前置 + A） | 隔离修订测试；作者能捞回超限稿，不因标点多付一次费 | 用模拟供应商计数；用隔离库覆盖生成、重开、审稿重试、采纳限制 |
| 2（P0-B） | 作者能给一条硬设定配检查条件，桌面和 Agent 能看到同一原句与结论 | 正反例、规则更新、修订后重审和跨入口重复录入通过 |
| 3（P1-A） | 缺章、写回状态、目标字数同屏；自动连写不会越过失败的前章 | 导入旧书、失败提交、授权跳写、批次恢复和修订不重复计数通过 |
| 4（P1-B） | 作者在书内核对时间、人数钱物、人物承诺；已确认新余额不再被旧卡抢回 | 跨章矛盾和合理留白均有对照案例；输出有两端证据或明确说缺哪项 |
| 5（P2） | 费用和代理原因有据可查；能录任意收尾章段、能改正式章名 | 桌面/MCP 同口径；历史用量缺项、价格未知、六章导向、正式改名分别有回归 |

实施时优先扩展 [章节任务契约验证](../scripts/validate-chapter-task-contract.mjs)、[Agent 流水线验证](../scripts/validate-agent-pipeline-execution.mjs)、[HardCanon 验证](../scripts/validate-hard-canon-pack.mjs)、[导向验证](../scripts/validate-story-direction-board.mjs) 和 [修订工具验证](../scripts/validate-agent-revision-tools.mjs)。新增一份脱敏的长篇合成样本，供全书核对与桌面/MCP 对照复用；不把作者未发表的正文放进仓库。每个改代码的批次跑定向测试、`npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build`；只有更新分发包时才做包内启动验收。自动检查不要依赖真实供应商有无密钥、代理或余额。

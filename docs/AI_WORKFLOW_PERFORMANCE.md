# AI 工作流性能基线

本页记录章节生成链路的可重复成本测量。测试只使用虚构中文数据，不读取用户小说，不调用真实模型，也不写入用户数据库。

## 草稿后分析

旧流程会把同一份章节正文和上下文分别发送给：

1. 章节复盘。
2. 角色变化提取。
3. 伏笔变化提取。

新标准流程使用一次结构化 `PostDraftAnalysisResult` 同时返回三类结果。旧方法仍保留，供旧任务和显式兼容路径使用。若统一响应失败，系统至多补做一次章节复盘，角色与伏笔候选保持为空并给出警告，不会盲目重放全部三个旧调用。

运行基准：

```powershell
node scripts/benchmark-post-draft-analysis.mjs --output tmp/performance/post-draft-analysis.json
```

输出会记录 Node 与平台、样本规模、热身次数、迭代次数、模型调用数、估算输入 token 和 prompt 构造 p50/p95。原始结果位于：

`tmp/performance/post-draft-analysis.json`

这些数字用于比较同一机器上的 before/after，不代表远程服务商响应时延。真实端到端效果仍需结合 Run Trace 的请求耗时、首次通过率和最终采纳结果判断。

## 当前边界

- 统一分析只发送本次上下文选中的角色、伏笔，以及正文中明确点名的对象。
- 所有提取结果仍是 pending 候选，不会自动写入角色、伏笔或长期记忆。
- 一致性审稿和质量门禁目前仍是独立调用；后续综合编辑结论完成后，标准单章正常路径才能从约 5 次进一步降到 4 次以内。
- 严格模式可继续保留独立复核，不能为了减少调用牺牲高潮章、揭露章和规则密集章的审稿质量。

## 一、目标与取舍

让作者或 Codex 可以连续完成：**想好下一章 -> 生成 -> 阅读 -> 修改 -> 采纳 -> 继续下一章**。正文由工作台配置的模型生成，导演负责创作判断；两种入口使用同一份数据、同一套正式提交和版本历史。

优化重点从“增加规则和页面”转向“减少返工、等待、页面往返和重复输入”。保留完整材料管理能力，但不要求先填满所有表格才能写作。

三个作者结果仍沿用原计划 M1-M3，表示验收维度，不另设一套施工顺序：

| 结果 | 作者能做什么 | 完成证据 |
| --- | --- | --- |
| M1 可靠完成一章 | 当前正文、报告和采纳一致；失败后可继续；知道打开的是哪一版 | 真实应用中走完生成、失败恢复、审阅、采纳、下一章；重启后正式记录可读 |
| M2 更快改好一章 | 改任务不用全章重来；从问题或选段直达改写；候选不白生成 | 局部任务更新与修订旅程通过，旧正文、候选和版本链保留 |
| M3 连续创作 | 人类和 Agent 可管理故事变化、审阅、决定、逐章提交 | Agent 不操作 UI 完成旅程，作者可接手相同数据；授权、暂停、恢复可用 |

### 创作决定与技术错误分开

| 情况 | 默认处理 | 导演保留的能力 |
| --- | --- | --- |
| 节奏、情绪、文风、有争议情节 | 给证据与建议，不用统一低分禁止创作 | 采纳、忽略、重写或调整任务 |
| 新规则、新人物、疑似机械降神 | 说明新增内容、来源和许可，不把关键词命中当最终事实 | 确认创作方向；是否写入长期设定另作明确决定 |
| 没有当前报告或报告过期 | 标为未审稿，提供重审 | 明确采纳正文；不得伪造通过或借用旧报告 |
| 候选尚未处理完 | 留在收件箱，不以清空待办作为下一章前提 | 部分接受、编辑、拒绝、暂缓、撤销 |
| 版本冲突、数据归属错误、事务失败 | 不伪报成功，不自动覆盖，保留用户结果 | 查看差异、重新定位、重试或保留候选 |
| 模型超时、取消、格式不完整 | 说明实际阶段，保留已完成步骤和可用结果 | 重试当前请求、修改下一次运行配置、手工继续 |

不建立“任何风险都要多点一次确认”的体系。预览内一次明确决定即可；真正改变正文、世界事实和权限的动作留痕，不为普通阅读和编辑反复弹窗。

### 本轮投入规则

- 先完成已开工的任务编辑和保存接线，验收、打包后再扩展下一项，减少半成品并存。
- 界面优先改善流水线、修订和阅读三个高频场景；暂不追求全站统一改版。
- Agent 优先补作者实际要用的世界资料管理与项目授权；已有工具不重写，不另造代理专用工作流。
- 质量、费用和长篇性能先取得小规模可重复数据，再决定改什么；不能把实验扩展为交付前三项的前置条件。
- 新增工作必须说明它解决哪一个实际痛点，或是否直接阻塞四项优先事项；否则留在候选清单。
- 已有事务、版本链、JSON 兼容、密钥保护和发布验证继续保留。这些是交付底线，不是另开一轮防御功能建设。

上一轮已复核流水线、任务契约、Prompt、保存和 Agent 边界。本次同步当前施工状态并调整优先级，以下不是新的全量审计或性能实测。

| 范围 | 已有能力，不重建 | 本轮实际缺口 |
| --- | --- | --- |
| 持久化与版本 | SQLite entity payload、JSON fallback、三类事务 bundle、候选命令、共享队列与 revision | 调用方未必接到专用接口；普通编辑仍有全量保存 |
| 生成 | 14 个可恢复步骤、计划后二次补全、配方、冻结的运行级模型配置；UI/Agent 九字段任务编辑和新运行已贯通 | 最终采纳质量、耗时和费用需要同条件测量 |
| Prompt | 优先级栈、HardCanon、伏笔分组/上限、预算/trace、运行时清理 | 正向任务需突出；去重和作品特例需校准，不继续堆禁令 |
| 审阅与采纳 | 正文绑定、综合结论、明确未审稿采纳、正式提交 | 主动作、候选决定、后台失败与实际采纳状态需全链路对齐 |
| 修订与阅读 | 正文优先布局、选区改写、重定位、暂存、对比、恢复与 Agent 修订工具 | 随本批触及场景回归，不另造编辑器或扩展全站改版 |
| 故事变化 | 事件分组、编辑后接受、部分选择、历史与补偿撤销 | 部分旧入口直接保存；自动时间线提取未闭合；旧记录无前值不能伪造撤销 |
| Agent | CLI/MCP、compact/full、任务、六类世界资料、审稿、提交、修订、版本、候选和项目授权 | 权限范围内逐章流程已闭合；下一项测读取与实际创作成本 |
| 性能与发行 | benchmark、包内 smoke、构建身份、原生绑定管理 | 需测最终采纳成本和长篇保存，不以文件变小代替收益 |

### 已定位的问题

1. **生成记录保存接线已修复。** `GenerationPipelineView.tsx` 已向 runner 透传专用保存；22 项交接检查含 12 项实际原生 SQLite 验证，覆盖需求/预算/trace 回读、失败与旧桥兼容，不以参数存在代替结果。
2. **任务编辑已贯通。** 五处类型错误已修复。九字段编辑、来源切换、保存、刷新恢复、生成和重试通过真实 Electron 检查；保存不调用 AI，三个本地 HTTP 计划/正文请求均携带新任务。旧产物保留，新上下文入队时验证项目资料没有变化。试用包验收状态见第三节与独立记录。
3. **作品特例已从通用任务硬校验中清理。** 明确字数、字面次数/位置和禁词继续检查；条件、建议和无法确定的情节语义只提示人工核对。换人物、换题材、否定、引用与软建议有回归，不用作品黑白名单替代通用规则。
4. **Agent 项目授权已闭合。** 作者在 Agent 页授予/撤回；绑定数据源、项目、动作和章节范围。范围内允许导演自主采纳、修订和入账，范围外回到人工决定，Agent 自填确认字段不能提权。独立世界编辑不要求先创建 job。
5. **长篇保存和 Agent 概览热点已局部优化。** 500 章样本中，修改一章保存 p50 从 826ms 降到 309ms，生成步骤 bundle 从 393ms 降到 1ms；完整 AppData API 与事务保持不变。四个 Agent 概览工具改为读取所需集合，摘要约 397ms -> 32ms，输出一致。桌面全量刷新与完整详情仍约 400ms，不先扩为全库 CRUD。

## 四、工作包实施说明

### W01：第一项接线与贯穿发行回归

**作者收益：** 打开的是包含改动的版本，使用的是预期的数据；已有事务能力真正生效。

1. 为 `GenerationPipelineView -> usePipelineRunner -> useAppData -> IPC -> StorageService` 补集成测试，覆盖专用保存和旧桥接缺方法时的兼容。
2. 修复参数透传；步骤保存后重新读取 job、steps、needs、budget、snapshot、trace，不只断言函数“被调用”。
3. 回归版本、构建时间、数据位置和实际后端；不同程序位置不能让用户误以为小说消失。
4. 每个可独立试用的功能批次验收后生成本地包、manifest、校验和和简短说明；分别记录源码、unpacked、安装包与 GitHub 发布。无需为每个内部施工卡或文档改动重复打包。
5. 复用 native 管理脚本处理 Node/Electron 绑定，不在测试运行时替换；结束全部测试进程。

主要边界：流水线页面/Hook、`useAppData`、Storage/IPC、`run-dist-win.mjs`。不新增数据库或发行目录体系。

**验收：** UI 的中间记录走专用接口，重启可读；无关项目不变；旧桥接可用。专用事务接口报错时不能用 full save 绕过校验。

### W02：已有采纳能力，随高频界面回归

**作者收益：** 看清当前正文和结论，一次采纳，能够继续。

沿用 `AuthorDecisionPolicyService`、`EditorialVerdict`、正文 hash 绑定与 `ChapterCommitBundle`。聚合“通过、建议修订、未审稿、保存冲突”四类作者状态，默认不展开重复报告。候选确认与正文采纳仍是不同动作。

重点回归：失败初稿 -> 修订 -> 当前报告通过 -> 采纳；旧失败报告不能参与当前决定；未审稿明确采纳后仍能继续；重复点击不重复创建版本；确认期间正文变化需展示实际提交内容。

审稿请求失败不等于正文不可保存，生成成功不等于已采纳。Dashboard、流水线和 Agent 共用决定策略，不各自猜测下一步。

### W03：只补阻塞主线的故事变化入口

**作者收益：** 同一事件不重复处理，已接受建议可以更正。

已交付 Inbox、编辑后接受、部分选择、决定历史和补偿撤销，本轮不重复新建。只处理优先事项 1-3 实际经过且仍有问题的入口，不要求先统一全部历史入口。

1. 当前入口缺共享决定或事务保存时补接线；普通手动编辑不必强行变成 AI 候选。
2. 保留原建议、实际采用值和变更前后；弱相关条目可分开，不强制整组接受。
3. 旧记录没有前值时只能查看或手动修正，不为完整撤销体验补造历史。
4. 自动时间线提取移入候选清单；第三项先保证人类和 Agent 都能手动维护时间线。以后加入提取时复用现有分析、生成 pending 候选，不默认新增 AI 调用。

边界：`CandidateDecisionService`、`DecisionInboxService`、normalizers、生成后分析、候选事务与 Agent 工具。

**验收：** 本批实际触及的候选入口能正确入账；拒绝不改事实，下一章读取决定后状态，撤销不回退后来正文。不要求新增自动提取才能完成主线。

### W04：已有修订能力，配合第二项改善阅读

**作者收益：** 看到哪一处不满意，就在附近改，不必理解修订系统内部结构。

章节、阅读页和修订台共用菜单与候选动作。保留空白重写、去 AI 味、自定义要求；支持“增强冲突”“对话更含蓄”等正向创作，不要求先造一条错误。

1. 证据直达正文；重复或失效证据由作者重选，不猜位置自动替换。
2. 候选旁显示原文、改写和差异，可再改、改要求、暂存、放弃、应用；局部与整章响应区分清楚。
3. 切页、重启、取消、响应迟到不丢有效结果；正式应用仍走 RevisionCommit。
4. 正文居中，章节跳转简洁；改完回到附近阅读位置，菜单不被裁切、不抢选区。

边界：`QuickRewriteDraftService`、`EditorialRevisionRequestService`、reading/revision、共享候选组件和版本提交。

**验收：** 未选文字不变，原文可恢复；过期候选仍可看可重定位；暂存不显示成正式修改。现有功能以集成修补为主，不新造编辑器。

### W05：第四项实测，按收益调整模型调用

**作者收益：** 知道在等什么，不因隐藏降级牺牲文章质量，不为同一分析重复花钱。

运行级配置、调用阶段、超时和取消已有基础。本轮先验证与测量现状，不把下面的检查项全部转成新功能任务；只修改可复现的不一致、重复调用或主要等待来源。

1. 保留五类运行角色配置，默认一个模型即可用；路由为高级设置。历史 run 冻结实际模型、参数和超时。
2. 显示准备、等响应、接收、重试与取消，不用假百分比。超时区分单请求剩余时间与整次操作预算。
3. 配方说明与真实执行一致。fast 跳过哪些检查必须说清，不能包装成同等审稿质量。
4. 复用统一生成后分析和综合语义审稿；只补当前缺失/失败或作者要求的检查，不默认“复审复审”。
5. HTTP 重试、格式降级和 CLI 共用可解释的调用预算，usage、原因可查；不能为提速暗中关能力、截正文或换模型。
6. 流式正文暂缓，不作为第四项交付条件。先分清模型生成慢、网络等待与本地处理慢。

边界：AIService、AIHttpClient、运行配置、PipelineRecipeService、分析服务和遥测。

**验收：** 慢响应、读取悬挂、429、格式降级、CLI 取消与重试可解释；取消不伤其他请求；正文完整。质量和最终成本由 W10 对照，不预先承诺省 token 比例。

### W06：第一优先，任务可编辑并真正生效

**作者收益：** 改一点想法，不必从头生成。

先用现有 ChapterTask 字段完成编辑：默认显示目标、冲突、结尾、篇幅、表达要求；悬念、伏笔使用/禁区和读者情绪可展开。角色焦点可先写在目标或冲突中，不为表单完备另造类型体系；空字段允许不填，不替作者编造任务。

本项先修复当前类型错误并接通页面，重点交付“文风修改、篇幅修改、剧情目标修改”三条链路和手动快照兼容。下面的矩阵规定相关修改被触及时的行为，不要求本批同时新增硬设定编辑器、模型路由或通用失效系统。

编辑后的任务用于下一次执行；原计划、Prompt、草稿和报告保留。运行中不静默改已发出的任务。“重试原运行”与“用新任务执行”分开；必要时创建新 job/快照，不覆盖历史成仿佛一开始就是新要求。

#### 字段影响矩阵

| 修改 | 要更新 | 可以复用 | 作者动作 |
| --- | --- | --- | --- |
| 文风、表达禁忌 | StyleEnvelope、写作限制、token 估算 | 角色/伏笔/Bridge 和选择；不超预算不重选 | 仅更新表达，保存不付费 |
| 篇幅 | 任务篇幅、输出预算、总预算检查 | 已有事实和计划，除非要求重排或预算不足 | 提示节拍密度，不自动增删剧情 |
| 目标、冲突、角色、结尾 | 任务、相关 needs、差量选择、最终 Prompt | 无关资料及旧产物 | 展示需求变化，一次重建，不自动重写 |
| 伏笔动作、硬状态、HardCanon | 相关 needs/上下文及需核对的诊断标记 | 无关章节/角色报告与历史 | 说明哪些依据改变，哪些只是建议更新 |
| 正文 | 当前 hash/revision、审稿与采纳依据 | 规划资料与旧报告历史 | 重审当前正文，不用旧文报告 |
| 模型、能力、超时 | 新运行或明确重试配置及 trace | 旧 run 冻结配置和结果 | 看见实际将用参数，不暗改历史 |
| 手动快照 | 作者新建/显式编辑的快照版本 | 原 finalPrompt 与手选范围 | 基于最新资料另建上下文，不自动补导向 |

实现顺序：

1. 在现有类型领域定义变化分组和轻量影响结果：changedFields、rebuildScope、reusableArtifacts、warnings。不先造通用依赖图。
2. 复用计划后二次补全、Planner/Budget 和 `buildPipelineContextResultFromSelection`，用局部更新协调器连接 UI/Agent。
3. 编辑器保存输入、展示影响，由作者选择更新上下文、重做计划或写正文；打字和保存不触发 AI。
4. 核对 retry 只恢复有效上游，不能把已被新任务替代的下游产物当作当前结果。
5. 新任务进入第一次上下文、ChapterPlan 和最终正文，避免页面改了但模型没看到。

#### 通用校验和 Prompt 减冗余

- 作品人物、专属来源询问和出行情节移回任务/fixture。字数范围、次数、位置、禁用短语可明确检查；隐式语义不擅自折成硬数字。
- 硬违约与建议分开；建议不能强制重试或冒充事实。保留作者明确约束，不以“少防御”抹掉任务。
- 正向行动目标在前，关键事实随后，最后少量独特限制。去重考虑对象、来源、否定和例外，不仅看词语相似。
- Bridge 优先；HardCanon 高于普通摘要，与 Bridge/任务冲突要显示差异；Story Direction 不能改 canon。
- 伏笔十条是上限不是配额，允许本章零推进。hidden/pause 不提及，payoff 只对明确允许对象；权重排序不改变语义。
- trace 对应真正送出的 Prompt；保留选择/压缩/省略原因，不把后台诊断重新写进正文指令。

边界：ChapterTask/ChapterPlan、ChapterTaskContractService、pipelineRuntimeBasics、计划后补全、formatter/guard、快照、任务显示组件。

**验收：** 三条编辑链路和手动快照逐项测试；换人物/题材、否定与引用不触发作品专属硬判断；文风小改不重选全部资料；目标新增角色需求进入实际 Prompt；旧产物可查看。正文绑定和冻结运行配置复用既有回归，不额外扩建。

### W07：第二优先，三个高频页面正文优先

**作者收益：** 打开就知道写到哪、下一步做什么，而不是面对全部内部模块。

| 页面 | 默认主区域 | 保留的辅助能力 |
| --- | --- | --- |
| 流水线 | 准备/生成/审阅/采纳四阶段，有草稿时正文优先 | 原始步骤、来源、trace 按需展开 |
| 章节/阅读 | 居中正文、简洁跳转、选区操作、明确编辑状态 | 版本链、回顾、全文 diff |
| 修订 | 原文/候选对比、应用/再改/保留 | 来源、模型、技术编号收起 |

视觉方向：沿用现有主题体系，以稳定正文宽度、明确字级、统一工具栏和辅助侧栏为主；减少嵌套卡片、重复标题、大块说明和泛滥状态色。主动作位置固定，保存/候选/正式版本术语一致。

本批不重做项目首页、资料页、设置、首用向导和独立 Prompt 页面。任务编辑需要的组件随第一项落地；其他页面只修直接阻塞当前旅程的问题。保留现有低门槛首用方式，不要求作者填完资料再写作。

每次改一个真实页面，保留完整功能。在 1280x720、1440x900 和约 960px 窄窗口测试长标题、空/忙/错状态、键盘、缩放、菜单、滚动；静态截图不能代替实际点击保存。

**验收：** 流水线阅读/采纳、修订比较/应用、连续阅读/跳章三条旅程不用原始 JSON 才能继续；正文和主动作无重叠；高级信息可展开；记录必要点击和往返是否减少。

**2026-09-07 交付：** Preview.7 已完成这三个页面。生成配置/历史、原文/审稿提示按需展开；24 组双主题四档窗口、8 组仅任务书状态通过真实指针与几何检查；完整包内 56 项旅程、111 张截图通过。阅读跳转改用滚动区坐标，恢复位置与主动跳章分别验收。没有扩大到全站重设计；详细边界见 [W07 试用记录](./OPTIMIZATION_W07_TRIAL.md)。

### W08：第三优先，Agent 世界管理与项目授权

**作者收益：** Codex 不看 UI 也能独立逐章创作，作者可随时接手。

| 能力 | 复用基础 | 补齐的闭环 |
| --- | --- | --- |
| 正文、任务、Prompt、版本、诊断读取 | compact/full 工具 | 完整信息按需可取，分页/截断可识别，不以摘要代替信息权 |
| 任务编辑与上下文重建 | W06 共享动作 | 同 UI 的影响预览、新运行和快照语义 |
| 角色/硬状态/伏笔/时间线/HardCanon/导向 | 现有领域服务与候选命令 | 缺失的精细编辑接共享动作，不复制 Agent 业务实现 |
| 审稿、采纳、修订、恢复 | 三类 bundle 和修订工具 | 实际 actor、来源、正式版本与 UI 结果一致 |
| 连续生产 | 单章执行器/批次工具 | 每章生成、审阅、决定、提交后继续；失败保留前序 |
| 授权与交接 | 预览与当前人工路径 | 作者在可信 UI 授权；Agent 不能给自己提权 |

授权先做简单项目设置：逐项确认，或在授予的章节/动作范围内执行。明确世界设定更改、未审稿采纳、高风险候选是否允许；范围内不重复人工确认。作者可撤回，已提交版本保留，撤回后不再发起新的越权写入。

不人为限制只能连续 2-3 章，支持作者指定 5、10 或几十章。连续的是标准单章流程，不是并行写完后批量伪造审核；下一章读取上一章实际采纳后的 Bridge 与角色状态。

工具默认 compact，提供稳定引用与下一动作；显式 full 获得完整必要材料。固定操作编号便于重试，不用 Computer Use 掩盖工具缺口。

**验收：** UI 候选由 Agent 修改/采纳后 UI 可读；逐章生产、暂停、恢复与作者中途修改；权限只暂停越界动作；其他项目不变；正文新增规则不自动成为 canon。

**2026-09-07 实现与实测：** 六类世界工具及操作回执、任务读取/预览/编辑、绑定当前正文和报告的明确采纳、候选与修订授权已接入。五章逐章旅程使用 21 次本地模拟响应通过，第三章暂停后恢复，作者第二章后的资料修改进入第三章。生产 Electron 项目授权页通过 60 项检查、22 张截图；授权不随小说备份传播，外部结果由作者主动读取。完整发行证据见 [W08 试用记录](./OPTIMIZATION_W08_TRIAL.md)，模拟响应不作为文学质量或费用结论。

### W09：第四项实测，按瓶颈优化长篇读写

**作者收益：** 小说长了仍能流畅编辑，UI 与 Agent 不互相覆盖。

1. 先修 W01，再测 10/100/500 章的输入/保存、步骤落盘、候选暂存、切项目、Agent 读取。记录数据规模、p50/p95、序列化/数据库/UI 刷新分段耗时。
2. 优先最高频热点。已采用更小改动：完整保存只写变化实体，生成 bundle 只读校验关联记录。只有局部优化收益仍不足时，再评估单章节命令；不一次拆完所有 CRUD。
3. 只有读取/规范化成为瓶颈才增加项目级查询与 selector；保持完整导出，不维护两份权威状态。
4. 不同对象的并发变化尽量合并；同一对象冲突保留双方结果，不要求无差别丢弃所有编辑。
5. 收益与故障测试成立再推广，不成立则保留简单实现。

边界：useAppData、正文保存 Hook、saveQueue、StorageService、SQLite entity entry 与项目选择器。

**验收：** 同机 before/after，无关集合不重写，无半写入；JSON、三类 commit 与候选撤销回归。SQLite 文件存在不等于更快。

**2026-09-07 实测：** 10/100/500 章样本完成 SQLite 和生产 Electron 对照；本地保存收益与尚未改善的全量读取分别记录。新增差异写入/定向读取回归和原始 JSON，详见 [W09/W10 实测记录](./OPTIMIZATION_W09_W10_MEASUREMENT.md)。不把 storage-only 毫秒数当作 UI 端到端耗时。

### W10：第四项实测，最终采纳效果与成本

**作者收益：** 少花无效 token、少整章返工，不是只得到更短的 Prompt。

先选覆盖当前痛点的少量虚构任务，例如续写、改文风、伏笔推进，记录材料版本、模型能力、预算和配方。先本地测组成/召回，再做有费用范围的远程对照；不自动使用真实稿件。只有结论不明确或新题材出现问题时才扩充样本，不先建大型评测工程。

| 测量 | 方法 | 判断 |
| --- | --- | --- |
| 最终采纳成本 | 累计规划、正文、审稿、修订、重试 usage；缺失标估算/未知 | 少一次审稿却多一次整章重写不算收益 |
| 端到端耗时 | 成功/失败都计入，分网络、本地、人工 | 更快得到愿意采纳的章节 |
| 创作质量 | 隐去配置比较动机、连贯、伏笔、语言、返工 | 小样本只作方向判断，不宣称普遍提质 |
| 召回 | 标注应选状态/伏笔/时间线/HardCanon，核对实际 Prompt | 关键覆盖不降，低价值回顾占用减少 |
| 禁令去重 | 对照否定、例外、对象不同的最小任务 | 独特限制不丢，诊断不混入写作 |
| Novelty | 中文真阳性、引用、否定、普通片段、实体边界和许可 | 降误报仍识别真实补丁；低置信度不阻断 |

FTS5、图谱和向量库不纳入本轮。测量先回答现有上下文是否足够、是否重复付费、是否真的拖慢保存，不因发现问题就默认新增检索层。

**验收：** 原始 JSON、环境、样本、before/after 和明确保留/放弃结论；不因投入过开发就设实验为默认。

## 五、目标架构和兼容边界

```text
作者 UI                         Codex CLI / MCP
   |                                  |
   +-------- 共享应用动作与预览 --------+
                    |
       既有领域服务 / 运行快照 / 正文绑定
                    |
       现有保存队列、IPC / Agent Storage
                    |
       SQLite 短事务 / JSON fallback / 版本链

AI：运行级配置 -> 既有模型桥 -> 调用遥测与取消
Prompt：任务 -> 需求 -> 预算 -> 拼装与 Guard -> Trace
```

- UI 负责编辑阅读反馈，不复制采纳、入账、恢复规则。
- 共享动作定义一次意图与影响，不先造覆盖全软件的泛化框架。
- GenerationRun 记录生成、ChapterCommit 记录采纳、RevisionCommit 记录正式修改，不合成长事务。
- 报告只说明它审过的正文；任务/正文更新不能让旧报告冒充最新。
- SQLite 不进入 renderer，小粒度写入逐项引入；跨进程保持 revision 与原子性。
- 旧类型、JSON、归档历史兼容；新字段有默认值，证据不足显示未知，不补造事实。

## 七、验收与收益

### 六条作者旅程

以下是验收样例库，不是每批都要重做的六个产品任务。第一项重点验收第 3 条和保存；第二项重点第 2、4 条；第三项重点第 6 条及所需世界资料操作；第四项对这些现有旅程测量。第 1、5 条作为被相关改动触及时的兼容回归。

1. 新用户配置 API 或 Codex CLI、测试连接，用一句想法写完第一章，不必填完整 Bible。
2. 打开项目、生成下一章、阅读当前结论、处理必要候选、采纳并继续。
3. 改文风/篇幅/角色，观察不同更新范围，保留旧计划和草稿并生成新版本。
4. 点证据或选段、改写、比较、再改、应用，回到阅读位置并重审当前正文。
5. 部分接受故事事件、编辑事实、撤销指定决定；下一章使用实际状态，正文版本不回退。
6. Agent 逐章生产、审阅和提交多章；人类中途接手、修订、撤回授权，数据一致。

### 每批验证

- 回归正文/报告绑定、三类提交、重复操作、队列并发、事务失败、JSON、密钥脱敏和旧数据 normalize。
- 运行 `npm.cmd run typecheck`、`npm.cmd test`、`npm.cmd run build`；发行再跑 `npm.cmd run dist:win`、packaged smoke 与真实页面 QA。
- 文档-only 批次只跑乱码、公开文档、链接和 `git diff --check`，不冒用历史业务结果。
- 使用隔离临时库、synthetic fixture、本地响应 stub；远程模型另设范围。结束 Electron/浏览器/服务进程。

### 衡量什么

| 指标 | 采集 | 目标，不是已有结论 |
| --- | --- | --- |
| 必要点击与往返 | 本批触及旅程，同入口任务对比 | 减少实际往返，不设统一百分比，不隐藏影响凑数字 |
| 最终采纳 token/耗时 | 关联 run/revision 累计，含失败返工 | 质量不降且成本改善，不承诺统一比例 |
| 操作等待 | 生产构建，预热、多轮 p50/p95，规模明确 | 同机改善；易抖 UI 指标先观测，不设脆弱 CI 线 |
| 正确性 | 约束、覆盖、版本、故障注入 | 关键行为不退化 |
| Agent 成本 | 往返、compact/full 读取量 | 同等信息权下少重复获取 |
| 可恢复性 | 取消、切页、重启、并发、迟到 | 不丢可用产物，不用旧状态覆盖新提交 |

复用 `perf:ui`、`perf:novelty`、`perf:prompt`、`perf:post-draft`。算法稳定预算可设门槛；UI/文学质量用同机同任务对照。每个“提升”附测量，不以源码行数、chunk 或测试数量单独证明。

## 八、发布、回退与范围

1. 每批固定基线和 fixture，再实现动作及调用方；验收后产生一个可试用包，不等待全盘结束。
2. 版本号在实际装包时确定；说明作者少做了什么、保留什么、验证与未验证范围。
3. 安装升级、签名、许可、隐私、教程与校验和按实际完成情况记录；本地打包不等于上传 GitHub。
4. 每批可独立退回代码/配置，但保留用户新正文、候选、提交历史；不能恢复整份旧库来“回滚实现”。
5. 模型/Prompt 实验无收益则不设默认；存储优化无收益不推广。

新框架、全库 CRUD、复杂 RBAC、图谱、云同步、向量检索和通用插件平台不在本轮范围。FTS、流式正文、项目级 store 也不作为四项主线的隐含任务；需要启动时另列问题证据与范围，不自动扩张当前验收。

| 剩余风险 | 处理 |
| --- | --- |
| 少检查导致更多返工 | 严格配方可选，最终采纳质量/成本决定默认 |
| 去重误删例外 | 按对象、来源、否定、例外做对照测试 |
| 自然语言不能完全确定校验 | 明确条件硬判，不确定建议，不持续加作品白/黑名单 |
| 全量与局部保存并存 | 调用方测试、共享队列/revision，逐项迁移 |
| Agent 越权或过度受限 | 作者授予可撤回范围，范围内不重复确认，客户端标志不提权 |
| 改版丢高级能力 | 逐页动作清单与旅程回归，收起而非删除 |
| 小样本不代表所有小说 | 明确题材/规模，不把一次成功变全局规则 |
| 历史包不等于当前源码 | 分开日期/版本/范围，发布前复测目标包 |
